## A tecnologia muda. O cuidado permanece.

Imagine precisar de atendimento social e enfrentar filas, formulários em papel, deslocamentos e informações espalhadas por diferentes processos.

Agora imagine uma experiência mais simples, na qual a triagem possa ser realizada digitalmente, as informações estejam organizadas e os profissionais tenham mais condições de se dedicar ao que realmente importa: **as pessoas.**

É essa transformação que inspira o PASI.

O **PASI — Plataforma de Atendimento de Sistemas Integrados** é uma solução voltada à digitalização e à organização da triagem dos serviços de assistência social, aproximando cidadãos e profissionais por meio de uma experiência digital mais acessível, integrada e humana.

Esta landing page apresenta a proposta do projeto, explica seus benefícios e orienta os visitantes sobre as possibilidades de utilização da plataforma.

## O problema que queremos transformar

A assistência social precisa de processos que facilitem o acesso ao atendimento, sem criar barreiras para quem já enfrenta dificuldades.

| O desafio de hoje | O que o PASI propõe |
| --- | --- |
| Fichas e formulários físicos | Formulários digitais organizados por etapas |
| Filas e tempo de espera | Possibilidade de realizar a triagem online |
| Informações dispersas | Informações reunidas em um sistema |
| Retrabalho administrativo | Processos mais organizados |
| Barreiras de acesso | Uma experiência pensada para diferentes públicos |
| Tempo consumido com burocracia | Mais espaço para o atendimento humano |

O objetivo não é substituir o profissional. É oferecer ferramentas que ajudem a tornar o atendimento mais organizado e eficiente.

## Acessibilidade não é um detalhe.

É parte da experiência.

Uma solução voltada à assistência social precisa considerar pessoas com diferentes níveis de familiaridade com a tecnologia, diferentes necessidades e diferentes formas de acessar informações.

Por isso, o projeto destaca princípios como:

- **Clareza:** conteúdo organizado e linguagem direta.
- **Organização por etapas:** formulários mais fáceis de acompanhar.
- **Apoio visual e sonoro:** recursos apresentados para facilitar a compreensão.
- **Flexibilidade:** possibilidade de atendimento presencial com apoio profissional.
- **Navegação acessível:** estrutura semântica, identificação de seções e suporte à navegação por teclado.
- **Respeito ao movimento:** consideração à preferência do usuário por movimento reduzido.

A proposta é que a tecnologia facilite o acesso, em vez de se tornar mais uma barreira.

### Tecnologias e recursos

- **React:** composição da interface com componentes reutilizáveis.
- **TypeScript:** tipagem e organização do código.
- **CSS3:** construção dos layouts, estilos e adaptações para diferentes telas.
- **Vite:** ambiente de desenvolvimento e execução do projeto.
- **Font Awesome:** biblioteca de ícones utilizada na interface.
- **Google Fonts:** utilização da família Montserrat.
- **CSS `@font-face`:** configuração da tipografia Smooth Circulars para os títulos.
- **React Hooks:** gerenciamento de estados, referências e comportamentos interativos.
- **Intersection Observer:** recurso utilizado pelo hook de revelação para acompanhar a entrada de elementos na área visível.

## Execute o projeto localmente

### Pré-requisitos

- Node.js instalado.
- npm disponível no terminal.
- Git, caso queira clonar o repositório.

### 1. Clone o repositório

```bash
git clone URL_DO_REPOSITORIO
```

### 2. Entre na pasta

```bash
cd NOME_DO_REPOSITORIO
```

### 3. Instale as dependências

```bash
npm install
```

### 4. Inicie o servidor de desenvolvimento

```bash
npm run dev
```

### 5. Abra no navegador

Utilize o endereço local exibido no terminal pelo Vite.

> Os comandos pressupõem que o `package.json` contenha o script `dev`. Os nomes do repositório e da pasta devem ser substituídos pelos valores reais.

## Configurações importantes

Algumas integrações são configuráveis e precisam ser ajustadas para o ambiente definitivo.

| Configuração | Arquivo | Finalidade |
| --- | --- | --- |
| Link de download | `src/data/links.ts` | Definir o destino real para acessar ou baixar o aplicativo. |
| Logotipo | `src/data/links.ts` | Centralizar os caminhos dos arquivos de identidade visual. |
| E-mail de contato | `src/data/links.ts` | Configurar o endereço que receberá as mensagens preparadas pelo formulário. |

Para configurar o e-mail, crie um arquivo `.env` na raiz do projeto:

```env
VITE_CONTACT_EMAIL=contato@exemplo.com
```

Substitua o endereço pelo e-mail correto e reinicie o servidor de desenvolvimento.

**Importante:** o formulário atual abre o aplicativo de e-mail do visitante com a mensagem preenchida. Ele não envia a mensagem automaticamente nem substitui uma integração com backend.

Da mesma forma, o endereço de download precisa ser configurado para direcionar o visitante ao destino correto.

## Nosso compromisso com a segurança

O PASI trata a segurança como parte importante da proposta, especialmente por envolver informações relacionadas à assistência social e potencialmente dados sensíveis.

A apresentação do projeto destaca:

- Níveis de acesso de acordo com os perfis de utilização.
- Organização das informações e dos processos.
- Redução da dependência de documentos físicos.
- Importância da proteção de dados e do acesso apropriado.

Esses princípios representam a proposta apresentada na landing page. A segurança efetiva depende das implementações e dos controles existentes na aplicação e em sua infraestrutura.
